# 万法 IDE GUI 修订建议

> 把上一轮审查里仍然成立的不顺手点，和你拍板的方向合在一起。  
> **V 键施放是另一套功能，和这套编辑器无关。**  
> **写入模式：画完立刻插入并清网格 —— 保持，不是问题。**

---

## 0. 已经拍板的原则

1. **Iota 主视图不要「方框接方框」**。不要再用 18×18 格子拼序列。主显示是 `IotaType.getDisplay()` 的文本，再用 HexParse 做合理排版（允许换行、空格、分段），读起来像代码/咒语，而不是物品栏。
2. **输入方式是窗口，不是切换条**。不要「网格 + HexParse / 仅 HexGrid / 仅 HexParse」那种选项卡。要换输入法：用叉号关掉当前窗口，再开一个新窗口。
3. **排布自由**。允许「左边输入、右边 Iota 文本」这类自己拼的布局，不要锁死「左树 / 中编辑 / 右目录 / 底下工具」。
4. **顶栏变窄**。少用文字，多用图标 + 悬停说明。
5. **窗口行为要现代**。现在的停靠/浮动只是能拖分割条和弹一个浮窗，缺撕下来、吸附、预览、最大化这些当代 IDE 的手感。

---

## 1. Iota 怎么显示

### 现状问题

中间 `SequenceEditorView` 是格子网：一格一个图案/色块。短法术还凑合，长法术变成扫雷，对不齐、看不出结构，也塞不下 `ListIota`、数字、实体这类非图案的含义。

### 目标

- **主视图 = 文本流**，每个 iota 显示 `IotaType.getDisplay(tag)`（图案用可读名，其它 iota 用类型色/原文）。
- **排版走 Parse**：有 HexParse 时用解析结果做「合理的」换行和空格（例如内省/反思成块、逗号后可换行、连续数字可同行）。没装 HexParse 时退回 `display()` 文本，仍允许手动换行/空格，只是不保证能反解析。
- 文本里可以点选某个 iota（高亮对应 token），插入点是光标，而不是「第 N 个空格子」。
- 图案仍可在 token 旁画一个很小的预览，但那是装饰，不是主交互面。
- 格子网如果还留，只作为可选视图窗口，不要当默认。

### 和输入的关系

- 画板写入：画完插入光标处并清网格（**保持现状，这没问题**）。
- 目录/搜索/笔记插入：同样插在文本光标。
- Parse 编辑窗口改的是同一份文档；主视图刷新的是 display/Parse 文本，而不是再铺一层格子。

## 2. 输入方式：关窗再开，不要切换条

### 删掉什么

- 底栏 `BottomToolDock` 的三个模式页签（`网格 + HexParse` / `仅 HexGrid` / `仅 HexParse`）。
- 「在同一个槽位里来回切」的心智。切来切去没有关窗的感觉，也看不出现在到底占用哪块空间。

### 改成什么

每种输入都是**独立窗口**（可停靠、可浮动）：

| 窗口 | 作用 |
|---|---|
| 画板（HexGrid） | 写入画图案，画完插入 |
| HexParse | 打代码，确认或失焦后再写回文档（不要打字 200ms 就 `replaceAll` 整页） |
| 图案目录 | 搜索 / 拖入 / 双击插入 |
| 书页树 | 管理页、笔记入口 |
| Iota 文本 | 主显示 + 光标 |

换输入：点标题栏 **× 关掉**，再从左侧/右侧工具条或命令（Ctrl+K）**新建/打开**该窗口。同一类窗口按需可以开两份（对照），不要用单选条互斥。

施法采集不要做成画板工具条上的「模式开关」。它要么是单独的采集窗口，要么沿用右键「施法」进明确的采集态。画板看起来要像编辑器，不要在窄条上藏一个会消耗媒质的模式。

---

## 3. 排布：自由停靠，而不是四宫格

默认不要再按「树 20% + 底栏 34% + 目录 24%」把主视图挤成一条。Minecraft GUI 很矮，**默认应先保证 Iota 文本能读**。

推荐的**出厂布局**（可改）：

- 中间 / 右侧：Iota 文本（主角）
- 输入窗口按用户自己放：例如左边画板或 Parse，右边文本；也可以底下一行画板
- 书页树、目录：默认可以收进条，用时再打开

允许的例子：

- 左画板、右 Iota 文本
- 左 Parse、右 Iota 文本
- 上文本、下画板（画板要够高才能画六边形；不够高就让用户自己拉，或撕出来变浮窗）
- 目录当浮动小窗，需要时再钉到边上

实现上不要把 dock 树写死成 `tree | ((editor / bottom) | catalog)`。用户拖窗口放到哪，哪就是布局。

## 4. 窗口行为要更现代（现在差得最多）

现在：分割条能拖、叶子能折叠、浮窗能拖标题和缩放、停回去变成 Tab。这是「能用的面板」，还不是现代窗口。

下面按手感补齐。没有这些，自由排布只是口号。

### 4.1 撕下来 / 钉回去

- **拖标题栏或 Tab 离开停靠区** → 变成浮动窗口（tear-off），不要只能点一个「浮动笔记」按钮。
- **把浮窗拖到主区域边缘或中央** → 出现停靠预览（左 / 右 / 上 / 下 / 变成该组 Tab），松手钉住。
- 钉回去是**停靠成面板**，不是只能「变回一个编辑器 Tab」。画板钉在左边、文本钉在右边，这才是自由排布。
- 标题栏 × = 关这个窗口（可从工具条再开）。不要和「关文档 Tab」混成一个语义。

### 4.2 停靠预览，不要盲放

拖到可停靠位置时画半透明落点（整侧高亮或 1/2 区域），让人知道松手后会左右分还是上下分。现在只有分割条热区，没有「我正在把这块放到哪」的反馈。

### 4.3 同一槽位用 Tab，而不是互斥模式

一个停靠槽里可以叠多个窗口（例如目录 + 书页树都在左边，用迷你 Tab 切）。切的是**这个槽里打开了谁**，不是全局「输入模式」。关掉 Tab = 从槽里拿走，槽空了就让给邻居。

### 4.4 最大化 / 临时占满

- 双击标题栏，或标题栏一个「最大化」图标：该窗口暂时吃掉整个停靠区，再点还原。
- 这在 MC 小分辨率上比「同时开四块」重要得多。画六边形、看长 Parse、对照两页，都该能一键放大。
- 双击分割条：两侧均分，或恢复上次比例。

### 4.5 浮动窗口本身

现在浮窗有拖、缩放、Z-order，还缺：

- 最小化到工具条（不是关掉、也不是叠在编辑器下面）
- 最大化到 IDE 工作区（仍在 GUI 内，不是 Minecraft 全屏）
- 贴边吸附（靠近另一浮窗或主区边缘时吸住）
- 记住每种窗口上次的浮/停、尺寸、位置（按法杖 UUID 的 workspace 里存）
- 点内容把窗口置顶（已有）之外：标题栏要一眼能看出谁在焦点（现在只有编辑器 Tab 顶上那条紫线）
- 浮窗不要被顶栏/底栏裁掉；拖出屏幕要钳位（已有 clamp 的话保持，缺的补）

### 4.6 工具条是「开窗」，不是「显隐一块固定面板」

左侧 20px 条现在是「折叠/展开固定的左树、底栏、右目录」，空间模型和窗口模型是拧的：

- 条上每个图标 = **打开或聚焦**对应窗口。已打开就聚焦；关了就按上次的停靠/浮动状态复活。
- 不要三个按钮全挤在左边，却去管右边的目录、底下的输入。条可以按边出现（左/右/底），图标贴在那一侧。
- 没有「神秘的展开比例」：关掉就是没这块，打开才占空间。

### 4.7 Tab 要能拖

- 编辑器 Tab 可以在分屏之间拖（现在分屏靠顶栏按钮或右键「向右/向下」，不能拖过去）。
- Tab 拖出栏外 = 撕成浮窗或落到另一个停靠槽。
- 关闭钮 10×10 太容易误点；图标化之后可保持小，但热区要大一点，并保留中键关闭。

### 4.8 不要用「重置布局」当主按钮

重置是救援，不是每天的操作。放进 Ctrl+K 命令或顶栏溢出菜单。日常调整全靠拖窗口。

### 4.9 ESC 分层

现在 ESC 基本等于关整个 IDE。现代一点：

1. 关右键菜单 / 搜索弹层 / 补全
2. 取消画板当前未完成笔划（若有）
3. 关最上层浮窗
4. 再按才退出 IDE（退出仍自动保存）

## 5. 顶栏

- **变窄**（高度可以低于现在的 26px），按钮几乎全是图标。
- 文字只留品牌或搜索框；「分屏对照 / 浮动笔记 / 咒法手册 / 重置布局 / 保存」全部改图标，悬停出说明。
- 搜索框在窄宽度下可以缩成一个放大镜，点开再展开（或只用 Ctrl+K）。
- 保存：编辑已经自动写回的话，顶栏保存不要摆成主按钮，避免「到底要不要按」；布局持久化跟关窗/拖完即可。
- 切回经典界面如果还要，做成设置或 Ctrl+K 命令，并真正写回 `almightly_staff.json`（现在只改内存，下次启动又是 IDE）。

## 6. 审查里仍然要改的不顺手点

这些和上面的方向不冲突，上一轮里你没否定的都列在这。

### 编辑与 Parse

- HexParse **不要 200ms 自动整页覆盖**。确认、失焦、或显式「应用」再写回。打到一半括号不齐时，主视图应保持上次合法内容。
- 补全不要劫持 Enter 换行（Tab 接受补全；Enter 在补全关闭时就是换行）。
- 代码/文本视图要能 **拖拽选区**，不能只靠键盘。
- 行高、点选热区按 MC 字体做够，11px 太挤。
- 「复制为文本」应复制能贴回 Parse 的代码，不要 `display()` 逗号拼接还叫 HexParse。
- 「导出 .hex」要么真是 HexParse，要么别用这个扩展名（现在是 NBT `toString()`）。
- 复制页后缀用「-副本」，不要 `" (copy)"`。
- 序列撤销和 Parse 输入框撤销不要各搞一套还互相冲；文档级 Ctrl+Z 是唯一真相，文本框未应用的草稿另算。

### 画板

- 写入即插入即清格：**保持**。
- 画板作为窗口必须能拉大；默认不要塞在 80px 高的底栏里。
- 最好能平移（现在滚轮只缩放 14～36，画到边缘会卡死）。
- ESC 先取消当前笔划，再关窗。
- 点空格/插入点不要再强制弹出全屏 `StaffDrawScreen`。画板窗口开着就地画；没开画板就打开画板窗口。

### 书页与命名

- 主视图旁要能看见/改法术名，不要只藏在树的 F2/右键。旧界面顶上那条名字框比现在顺手。
- 新建 / 复制 / 删除要找得到（树顶 `+` / `D+` 无说明，删除还要连点两次且几乎无界面反馈）。图标 + tooltip 即可。
- 树注释写「单击选中、双击开 Tab」，代码里单击已经打开。要么真做成单击选、双击开，要么改文案。
- 首次不要把英文示例笔记、外部手册默认全展开，压过法术页列表。

### 搜索与快捷键

- 双击 Shift 在输入框聚焦时无效，序列里 Shift 多选又容易误触。更稳的是 Ctrl+K；双击 Shift 可留，但不要当主入口。
- 搜索选中图案不要直接插入（或至少区分「跳转到目录」和「插入」）。回车插图案太容易误伤。

### 采集与危险操作

- 「施法采集」不要做成画板工具条上静静亮着的模式。真消耗媒质，窄画板里栈还只显示 4 条。改成独立窗口或明确的开始/结束。
- 底栏不要写「按 V 施放当前选中页」。V 与本 GUI 无关；这句话在编辑器里会造成错觉。

### 其它

- 浮动笔记不要永远打开列表第一篇，应能选、或从树里拖出来。
- 顶栏「分屏」只左右拆、Tab 右键才能上下拆：等 Tab 可拖、可撕之后，这两个入口可以收掉。
- 手册/外部 Screen 嵌入时，不要默默顶掉当前法术 Tab；最好进自己的窗口。

---

## 7. 明确保持不变

- 写入模式：画完插入光标并清空网格。
- V 键施放：不在这套 GUI 里绑「点开哪页就施放哪页」。
- 自动保存文档内容（改了就写回服务端）。
- 封存页：可改名/复制，不能改内容/删除/重排。
- 客户端仍然只拿 iota 的原始 NBT，显示用 `getDisplay` / `getColor`；Parse 往返走现有 IDE 协议。
- 像素风、禁止 emoji、裁剪走 `IdeScissor`、中文 IME 用唯一 `FocusManager`。

---

## 8. 建议落地顺序

不按旧 M0–M9 重写，按手感依赖排：

1. **Iota 主视图改成 display/Parse 文本**（换行、空格、光标、点选 token）。格子退成可选。
2. **拆掉底栏模式条**；画板、Parse、目录、树变成可关可开的窗口。
3. **窗口现代化**：撕下、停靠预览、槽内 Tab、标题栏 ×、最大化、条上图标 = 开窗。没有这一层，自由排布落不了地。
4. **出厂布局改成「文本为主，输入按需」**，适配 MC 矮 GUI。
5. **顶栏图标化、变窄**；重置/保存/分屏从主路径拿掉。
6. Parse 改为显式应用；补全/拖选/复制导出/采集窗口这些跟手细节。

先做 1–3，这套 GUI 才会开始像「可摆的编辑器」，而不是「把 IDEA 面板默认全打开塞进 Minecraft」。
